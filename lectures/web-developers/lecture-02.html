1. База данных и проблема хранения информации

1.1. Понятие базы данных

База данных (БД)

Организованная совокупность взаимосвязанных данных, предназначенная для длительного хранения, поиска, обработки и использования информации.

Базы данных используются в банках, интернет-магазинах, социальных сетях, образовательных учреждениях, больницах, системах бронирования и государственных информационных системах.

Пример. В колледже необходимо хранить информацию о студентах, группах, дисциплинах, преподавателях, оценках и посещаемости. При 10 000 студентов и большом числе учебных данных простого хранения недостаточно: данные нужно правильно организовывать.

1.2. Проблемы неструктурированного хранения данных

Студент Группа Предмет 1 Оценка Предмет 2 Оценка
Иванов Иван ИСП-21 Базы данных 5 Программирование 4
Петрова Анна ИСП-21 Базы данных 5 Программирование 5

Такая организация неудобна.

  • Повторение информации: название группы и дисциплин повторяется во многих строках.
  • Сложность изменения: одно изменение приходится выполнять в нескольких местах.
  • Ошибки: значения вроде «ИСП-21», «ИСП21» и «ИСП 21» могут восприниматься как разные.
  • Сложность расширения: новая дисциплина приводит к необходимости добавлять новые столбцы.
  • Противоречивость: одна и та же информация может оказаться различной в разных строках.
  • Сложность поиска и обработки: с ростом объёма данных работа становится менее удобной и эффективной.
Важно
Когда данных становится много, их необходимо не просто хранить, а структурировать.

2. Модель данных

2.1. Понятие модели данных

Одну и ту же информацию можно представить разными способами. Город можно представить фотографией, картой, схемой метро или навигатором. Объект один и тот же, но способы его представления различаются.

Модель данных

Совокупность принципов, определяющих, как представлены данные, какова их структура, как данные связаны между собой, какие операции над ними выполняются и какие правила должны соблюдаться.

2.2. Основные модели данных

Иерархическая модель

Данные организованы в виде дерева: колледж → отделение → группа → студент.

Сетевая модель

Объекты могут иметь множество различных связей. Такая структура гибче дерева.

Реляционная модель

Данные представлены в виде взаимосвязанных таблиц. Именно эта модель будет основной темой лекции.

3. Реляционная модель данных

3.1. Понятие реляционной модели

Слово реляционная происходит от английского relation — «отношение».

Реляционная модель данных

Модель организации данных, в которой информация представляется в виде отношений, то есть таблиц. Таблицы могут быть связаны между собой.

3.2. Основные элементы реляционной модели

Термин Практическое название
Отношение Таблица
Атрибут Столбец, поле
Кортеж Строка, запись
Значение атрибута Значение ячейки

3.3. Отношение

Отношение

Структурированный набор данных об объектах определённого типа, представленный в виде таблицы.

Например: отношения «Студенты», «Группы», «Дисциплины».

3.4. Атрибут

Атрибут

Свойство объекта, представленное столбцом таблицы.

В таблице «Студенты» атрибутами могут быть ID, Фамилия, Имя, Группа.

3.5. Кортеж

Кортеж

Строка отношения, то есть одна запись таблицы.

3.6. Значение атрибута

Это конкретное значение, находящееся в ячейке: например, Фамилия = Иванов, Группа = ИСП-21, ID = 1.

3.7. Домен

Домен

Множество допустимых значений, которые может принимать атрибут.

Атрибут Пример допустимых значений
Оценка 2, 3, 4, 5
Возраст Целые положительные числа
Дата рождения Значения, соответствующие типу даты
Примеры недопустимых значений

Возраст = «Понедельник»; Оценка = 100; Дата рождения = «Слон».

4. Свойства реляционной таблицы

  1. Каждая таблица имеет уникальное имя.
  2. Каждый столбец имеет имя.
  3. Значения одного столбца принадлежат одному домену.
  4. Каждая строка описывает отдельный объект.
  5. Строки не должны дублировать друг друга.
  6. Порядок строк не имеет смыслового значения.
  7. Порядок столбцов также не является смысловой характеристикой: смысл определяется атрибутами и их значениями.
Пример

Если поменять местами строки с Ивановым и Петровой, набор хранимой информации не изменится.

5. Реляционные объекты и ключи

5.1. Зачем нужны ключи?

По сочетанию «Фамилия + Имя» не всегда можно гарантированно определить конкретного человека. У двух студентов может быть одинаковое имя и фамилия, поэтому нужен уникальный идентификатор.

Иванов Иван ИСП-21
Иванов Иван ИСП-22

После добавления ID записи можно однозначно различать.

ID Фамилия Имя Группа
1 Иванов Иван ИСП-21
2 Иванов Иван ИСП-22

6. Ключи

Ключ

Атрибут или набор атрибутов, используемый для идентификации записи или установления связи между таблицами.

6.1. Первичный ключ

Первичный ключ (Primary Key, PK)

Атрибут или набор атрибутов, однозначно идентифицирующий каждую запись таблицы.

Свойства:

  • уникален;
  • не повторяется;
  • не содержит пустых значений;
  • однозначно идентифицирует запись.

Примерами уникальных идентификаторов могут быть номер студенческого билета, номер паспорта, VIN автомобиля, серийный номер устройства или уникальный идентификатор пользователя.

7. Связывание таблиц

Разделение данных на таблицы уменьшает повторение информации и упрощает её изменение.

ID Фамилия ID_группы
1 Иванов 1
2 Петрова 1
3 Сидоров 1
ID_группы Название Куратор Кабинет
1 ИСП-21 Смирнов 304
Главное преимущество
Информация о группе хранится один раз, а студенты ссылаются на неё через ID_группы.

8. Типы связей между таблицами

8.1. Один к одному — 1 : 1

Одной записи первой таблицы соответствует одна запись второй. Пример: человек — паспорт.

8.2. Один ко многим — 1 : M

Одной записи первой таблицы соответствует множество записей второй. Пример: одна группа содержит множество студентов, при этом один студент относится к одной группе.

8.3. Многие ко многим — M : M

Один студент может изучать несколько дисциплин, а одну дисциплину изучают многие студенты.

Тип Обозначение Пример
Один к одному 1:1 Человек — паспорт
Один ко многим 1:M Группа — студенты
Многие ко многим M:M Студенты — дисциплины

Реализация связи M : M

9. Ссылочная целостность

9.1. Проблема неправильных ссылок

Пусть в таблице «СТУДЕНТЫ» у Петровой стоит ID_группы = 7, но группы с ID = 7 не существует. Это некорректная ссылка.

Ссылочная целостность

Правило согласованности связанных таблиц, согласно которому внешний ключ должен ссылаться только на существующую запись другой таблицы.

Простая формулировка
Нельзя создать ссылку на то, чего не существует.

9.3. Проблема удаления связанных данных

Если удалить группу ID = 1, а в таблице студентов останутся записи с ID_группы = 1, появятся ссылки на несуществующую запись. Это нарушает ссылочную целостность.

10. Действия при удалении и изменении связанных данных

Действие Значение
RESTRICT Запретить операцию, если есть связанные записи.
CASCADE Автоматически выполнить операцию для связанных записей.
SET NULL Установить внешнему ключу значение NULL.
SET DEFAULT Установить значение по умолчанию.
Осторожно с CASCADE
Автоматическое каскадное удаление может привести к массовому удалению связанных данных.

11. Ограничения целостности

Ограничения целостности

Правила, контролирующие корректность и согласованность данных.

Они не позволяют базе принимать любые значения. Например, возраст = -25, оценка = 100 или дата рождения = «Слон» должны быть исключены соответствующими правилами.

13. Индексирование

13.1. Проблема поиска

Если в таблице 1 000 000 студентов и нужно найти ID = 857392, последовательный просмотр большого количества записей может быть дорогим.

13.4. Какие поля индексируют?

Обычно индексы создают для полей, по которым часто выполняются поиск, сортировка или соединение таблиц. В качестве кандидатов могут выступать ID, Фамилия и Группа.

14. Преимущества и недостатки индексов

ПреимуществаУскоряют поиск, выполнение запросов, некоторые операции сортировки и соединения таблиц.
НедостаткиЗанимают место и требуют обслуживания; могут замедлять добавление, изменение и удаление данных.
Главное правило
Индекс ускоряет чтение данных, но может замедлять их изменение. Поэтому нельзя создавать индексы на всех полях без необходимости.

15. Правила Кодда

15.1. Кто такой Кодд?

Эдгар Ф. Кодд сформулировал реляционную модель данных и предложил набор принципов, позволяющих оценивать соответствие системы идеям реляционной модели.

Правила Кодда

Набор принципов и требований, определяющих характеристики полноценной реляционной системы управления базами данных.

В учебном материале выделяется нулевое правило и двенадцать основных правил. На начальном этапе важнее понимать их смысл, чем запоминать формулировки дословно.

16. Основные правила Кодда

Правило Смысл
0. Нулевое Система должна управлять БД с использованием реляционных возможностей.
1. Информационное Вся информация представляется в виде значений в отношениях, то есть таблицах.
2. Гарантированный доступ К каждому значению можно обратиться по имени таблицы, идентификатору записи и имени столбца.
3. NULL Система должна корректно работать с отсутствующими или неизвестными значениями. NULL не равен 0 и не равен пустой строке.
4. Реляционный каталог Информация о таблицах, столбцах, типах данных и ограничениях должна быть доступна из самой системы.
5. Полный язык Должен существовать язык для создания структуры, работы с данными, поиска и управления доступом; пример — SQL.
6. Обновляемость представлений Некоторые представления должны поддерживать возможность обновления.
7. Работа с наборами Операции должны выполняться не только над отдельными записями, но и над наборами данных.
8. Независимость физических данных Изменение физического способа хранения не должно требовать изменений прикладных программ.
9. Независимость логических данных Изменение логической структуры должно минимально влиять на приложения.
10. Независимость ограничений Правила целостности должны определяться самой базой данных.
11. Независимость распределения Пользователь не должен зависеть от физического расположения данных.
12. Отсутствие обхода правил Нельзя обходить ограничения целостности через низкоуровневые механизмы.
Основная идея
Реляционная система должна представлять данные в виде отношений, обеспечивать доступ к данным, корректно работать с NULL, иметь язык работы с данными, работать с наборами, поддерживать независимость данных и обеспечивать целостность.

В учебном материале рассматриваются: выборка, проекция, объединение, пересечение, разность, декартово произведение и соединение.

18.3. Объединение

Обозначение: ∪. Объединяет данные двух совместимых отношений.

18.4. Пересечение

Обозначение: ∩. Возвращает элементы, присутствующие одновременно в двух отношениях.

18.5. Разность

Обозначение: −. Возвращает записи, которые находятся в первом отношении, но отсутствуют во втором.

18.6. Декартово произведение

Обозначение: ×. Создаёт все возможные комбинации строк двух отношений. Если первая таблица содержит m строк, а вторая n строк, результат может содержать m × n строк.

24. Самое важное, что нужно запомнить

  1. Реляционная база данных хранит информацию в виде таблиц.
  2. Столбец называется атрибутом, строка — кортежем или записью.
  3. Первичный ключ уникально идентифицирует запись.
  4. Внешний ключ связывает таблицы.
  5. Основные типы связей: 1:1, 1:M, M:M.
  6. Связь M:M реализуется через промежуточную таблицу.
  7. Ссылочная целостность запрещает ссылки на несуществующие записи.
  8. Ограничения целостности защищают данные от ошибок.
  9. Индекс ускоряет поиск, но может замедлять изменение данных.
  10. Правила Кодда определяют основные принципы реляционной СУБД.
  11. Реляционная алгебра определяет операции над таблицами.
Ключевая разница

Выборка → выбирает строки.

Проекция → выбирает столбцы.

JOIN → соединяет связанные таблицы.

Итоговая логическая цепочка

Данные организуются в таблицы. Таблицы состоят из атрибутов и кортежей. Для уникальной идентификации используются первичные ключи. Внешние ключи создают связи между таблицами. Ссылочная целостность обеспечивает корректность этих связей. Ограничения защищают данные от ошибок. Индексы ускоряют поиск. Реляционная алгебра определяет операции над таблицами, а SQL позволяет применять эти операции на практике.

Самопроверка

Попробуйте ответить самостоятельно, затем откройте ответ.

1. Что является основным способом представления данных в реляционной модели?
Таблицы, или отношения.
2. Как называется столбец таблицы?
Атрибут.
3. Как называется строка таблицы?
Кортеж или запись.
4. Для чего нужен первичный ключ?
Для однозначной идентификации каждой записи таблицы.
5. Для чего нужен внешний ключ?
Для связи таблиц и поддержки ссылочной целостности.
6. Какой тип связи между группой и студентами?
Один ко многим — 1:M.
7. Как реализуется связь многие ко многим?
Через промежуточную таблицу.
8. Что такое ссылочная целостность?
Правило, согласно которому внешний ключ должен ссылаться только на существующую запись.
9. Для чего нужен индекс?
Для ускорения поиска и обработки данных.
10. Чем выборка отличается от проекции?
Выборка выбирает строки, а проекция — столбцы.
11. Для чего используется JOIN?
Для соединения связанной информации из нескольких таблиц.
12. Что такое реляционная алгебра?
Система операций над отношениями, результатом которых также является отношение.
