1. Почему данные нужно правильно организовывать?

Представим базу данных колледжа, в которой нужно хранить сведения о студентах, группах, дисциплинах и оценках.

Если записывать всё в одну большую таблицу, одни и те же сведения начинают повторяться, а изменение данных становится сложным и опасным.

Студент Группа Предмет 1 Оценка Предмет 2 Оценка Предмет 3 Оценка
Иванов ИСП-21 БД 5 Программирование 4 Математика 5
Петрова ИСП-21 БД 5 Программирование 5 Математика 4

Проблемы такой структуры

  • одни и те же сведения повторяются;
  • сложно добавлять новые дисциплины;
  • поиск становится неудобным;
  • при изменении данных легко допустить ошибку;
  • разные записи могут начать противоречить друг другу.
📌 Основная мысль
Когда данных становится много, важно не только их хранить, но и правильно организовать их структуру.
База данных (БД)
Организованная совокупность взаимосвязанных данных, предназначенная для длительного хранения, поиска и обработки информации.

Основные проблемы неструктурированного хранения данных:

  • повторение информации;
  • ошибки при изменении;
  • сложность поиска;
  • противоречивость данных;
  • неудобство обработки.

2. Что такое модель данных?

Один и тот же объект можно представить по-разному. Например, город можно показать на фотографии, карте или в навигаторе. Сам объект остаётся тем же, но способ представления информации меняется.

Модель данных
Совокупность принципов, определяющих структуру данных, связи между данными и способы работы с ними.

Модель данных определяет:

  • как представлены данные;
  • как данные связаны между собой;
  • какие операции можно выполнять;
  • какие правила должны соблюдаться.

Основные модели данных

Иерархическая модель

Данные организованы по принципу дерева: один элемент может иметь подчинённые элементы. 

Колледж
│
├── Отделение
│   │
│   ├── Группа
│   │   │
│   │   └── Студент

Сетевая модель

Объекты могут иметь множество связей между собой.

Реляционная модель

Данные представлены в виде таблиц, которые могут быть связаны друг с другом. 

СТУДЕНТЫ

ID | Фамилия | Группа
📌 Главное
В этой лекции мы изучаем реляционную модель и её основные принципы.

3. Реляционная модель данных

3.1. Откуда произошло слово «реляционная»?

Слово происходит от английского relation — «отношение». Поэтому в реляционной модели таблица рассматривается как отношение.

3.2. Основные элементы отношения

ОТНОШЕНИЕ → ТАБЛИЦА

Отношение

Отношение
Таблица, содержащая данные об объектах определённого типа.

Атрибут

Столбец таблицы называется атрибутом.

ID Фамилия Имя Группа
1 Иванов Иван ИСП-21
2 Петрова Анна ИСП-21
3 Сидоров Максим ИСП-22

Атрибуты этой таблицы: ID, Фамилия, Имя, Группа.

Кортеж

Строка таблицы называется кортежем. В практической работе часто говорят «строка» или «запись».

Домен

Каждый атрибут имеет допустимый набор значений. Этот набор называется доменом.

Атрибут Пример допустимых значений
Оценка 2, 3, 4, 5
Возраст целые положительные числа
Дата рождения значения типа DATE
⚠️ Важно
Значение атрибута должно соответствовать его допустимому набору значений и установленным ограничениям.

3.3. Свойства реляционной таблицы

  • таблица имеет имя;
  • столбцы имеют имена;
  • данные одного столбца относятся к одному типу;
  • строки описывают отдельные объекты;
  • строки не должны дублироваться;
  • порядок строк не влияет на смысл данных.
💡 Проверка понимания
Если поменять местами две строки таблицы, сама информация от этого не изменится. В реляционной модели порядок строк сам по себе не является смысловой характеристикой.
Запомните
Отношение — таблица.
Атрибут — столбец.
Кортеж — строка.
Значение атрибута — конкретное значение в ячейке.
Домен — множество допустимых значений атрибута.

4. Реляционные объекты и ключи

4.1. Зачем нужны ключи?

Фамилия и имя не всегда однозначно определяют человека. В одной таблице могут существовать несколько одинаковых значений.

Фамилия Имя Группа
Иванов Иван ИСП-21
Иванов Иван ИСП-22

Поэтому для каждой записи нужен идентификатор, который позволяет однозначно отличить её от остальных.

4.2. Первичный ключ

Первичный ключ (Primary Key, PK)
Атрибут или набор атрибутов, однозначно идентифицирующий каждую запись таблицы. 
ID_студента

Для первичного ключа важны:

  • уникальность;
  • отсутствие повторяющихся значений;
  • отсутствие пустых значений.

4.3. Внешний ключ

Таблицы базы данных связаны между собой через значения ключей. Например, студент может ссылаться на группу по её идентификатору.

ID_группы Название
1 ИСП-21
2 ИСП-22
ID_студента Фамилия ID_группы
1 Иванов 1
2 Петрова 1
3 Сидоров 2
Внешний ключ (Foreign Key, FK)
Поле одной таблицы, которое ссылается на ключ другой таблицы. 
ГРУППЫ
-----------------
ID_группы (PK)
Название
       ▲
       │
       │
СТУДЕНТЫ
-----------------
ID_студента (PK)
Фамилия
ID_группы (FK)
📌 Запомните
PK идентифицирует запись.
FK связывает таблицы.

5. Связывание таблиц

5.1. Зачем разделять данные?

Если одни и те же сведения повторяются во многих строках, их удобнее вынести в отдельную таблицу и связать таблицы ключами.

Студент Группа Куратор Кабинет
Иванов ИСП-21 Смирнов 304
Петрова ИСП-21 Смирнов 304
Сидоров ИСП-21 Смирнов 304
📌 Главная идея
Разделение информации на таблицы уменьшает дублирование и упрощает изменение данных.

5.2. Связь «один к одному»

1 : 1

Одной записи первой таблицы соответствует одна запись второй, и наоборот. 

ЧЕЛОВЕК ───────── ПАСПОРТ

5.3. Связь «один ко многим»

1 : M

Одной записи первой таблицы соответствует множество записей второй. 

ГРУППА ─────< СТУДЕНТЫ

Одна группа может содержать много студентов, а конкретный студент относится к одной группе.

5.4. Связь «многие ко многим»

M : M

Студент может изучать несколько дисциплин, а одну дисциплину могут изучать многие студенты. 

СТУДЕНТЫ ←→ ДИСЦИПЛИНЫ
⚠️ Важный момент
Связь M:M реализуется через промежуточную таблицу.

УСПЕВАЕМОСТЬ

ID_студента ID_дисциплины Оценка
1 1 5
1 2 4
2 1 5 
СТУДЕНТЫ                 ДИСЦИПЛИНЫ
    │                         │
    │                         │
    └─────────┐   ┌───────────┘
              ▼   ▼
          УСПЕВАЕМОСТЬ
Типы связей
1 : 1 — один к одному.
1 : M — один ко многим.
M : M — многие ко многим.

Связь M:M реализуется через промежуточную таблицу.

6. Ссылочная целостность

Внешний ключ должен ссылаться на существующую запись. Иначе таблицы могут содержать ссылки на объекты, которых уже нет.

ID Название
1 ИСП-21
2 ИСП-22
ID Фамилия ID_группы
1 Иванов 1
2 Петрова 7

Группы с ID = 7 не существует. Значит, внешний ключ содержит недопустимую ссылку.

Ссылочная целостность
Правило, согласно которому внешний ключ должен ссылаться только на существующую запись другой таблицы.
💡 Простая формулировка
Нельзя создать ссылку на то, чего не существует.

Что происходит при удалении связанной записи?

RESTRICT

Удаление запрещается, пока существуют связанные записи.

CASCADE

Связанные записи удаляются автоматически.

⚠️ Осторожно
CASCADE нужно использовать осознанно: удаление одной записи может привести к удалению связанных данных.

SET NULL

Значение внешнего ключа устанавливается в NULL.

SET DEFAULT

Устанавливается значение по умолчанию.

Запомните
RESTRICT — запретить удаление.
CASCADE — удалить связанные записи.
SET NULL — установить NULL.
SET DEFAULT — установить значение по умолчанию.

7. Ограничения целостности

База данных должна контролировать корректность хранимой информации. Не каждое значение является допустимым. 

Возраст = -25
Оценка = 100
Дата рождения = "Слон"
⚠️ Проблема
Такие значения могут не соответствовать правилам, установленным для конкретных полей.

Основные ограничения

NOT NULL

Поле не может быть пустым. 

Фамилия NOT NULL

UNIQUE

Значения не должны повторяться. 

Номер студенческого билета UNIQUE

PRIMARY KEY

Уникальный идентификатор записи.

FOREIGN KEY

Обеспечивает связь между таблицами и поддерживает ссылочную целостность.

CHECK

Позволяет установить условие для допустимых значений. 

CHECK (Оценка >= 2 AND Оценка <= 5)

DEFAULT

Устанавливает значение по умолчанию. 

Статус = 'Активен'
Ограничение Назначение
NOT NULL Значение обязательно
UNIQUE Значение уникально
PRIMARY KEY Идентификация записи
FOREIGN KEY Связь таблиц
CHECK Проверка условия
DEFAULT Значение по умолчанию
📌 Главное
Ограничения целостности — это правила, которые контролируют корректность данных.

8. Индексирование

Представьте обычный словарь. Чтобы найти слово, не нужно читать его целиком: порядок слов позволяет быстро перейти к нужному месту.

💡 Аналогия
Индекс в базе данных можно представить как специальный указатель, помогающий быстрее находить нужные данные.

Проблема поиска

В таблице может находиться очень много записей. Если часто искать данные по определённому полю, полный просмотр всей таблицы может быть неэффективным. 

БЕЗ ИНДЕКСА

Запрос → просмотр большого количества записей
           │
           ▼
        нужная запись

Понятие индекса

Индекс
Специальная структура данных, предназначенная для ускорения поиска информации. 
С ИНДЕКСОМ

Запрос
   │
   ▼
ИНДЕКС
   │
   ▼
Нужная запись

По каким полям могут использоваться индексы?

Например, в таблице студентов часто выполняется поиск по:

  • ID;
  • фамилии;
  • группе.

Плюсы и минусы

Преимущества Недостатки
Ускоряют поиск Занимают дополнительную память
Ускоряют некоторые запросы Могут замедлять добавление данных
В некоторых случаях помогают при сортировке Могут замедлять изменение данных
⚠️ Важно
Больше индексов не означает автоматически лучшую производительность.
📌 Запомните
Индекс ускоряет чтение, но может замедлять операции изменения данных. Поэтому индексы создают осознанно, прежде всего для часто используемых путей поиска.

9. Правила Кодда

Эдгар Кодд сформулировал принципы, описывающие свойства реляционной системы управления базами данных. Эти принципы называют правилами Кодда.

💡 Как их изучать
Для первого знакомства достаточно понять общий смысл правил. Необязательно механически запоминать их дословные формулировки.

Нулевое правило

Система должна управлять базой данных с использованием реляционных возможностей.

Правило 1. Информационное

Информация представляется в виде данных в отношениях (таблицах).

Правило 2. Гарантированный доступ

К каждому отдельному значению можно обратиться через имя таблицы, первичный ключ и имя столбца.

Правило 3. Систематическая обработка NULL

Система должна корректно работать с отсутствующими или неизвестными значениями.

NULL — это не то же самое, что 0
NULL не следует автоматически считать ни нулём, ни пустой строкой. Он может обозначать отсутствие или неизвестность значения.

Правило 4. Реляционный каталог

Информация о структуре базы данных также должна быть доступна как данные.

Правило 5. Полный язык работы с данными

Система должна предоставлять язык для создания структуры, работы с данными и управления доступом. Пример такого языка — SQL.

Правило 6. Обновляемость представлений

Некоторые представления данных должны поддерживать возможность обновления.

Правило 7. Операции над наборами данных

Реляционные операции должны работать не только с одной записью, но и с наборами данных. 

Не только:
изменить одного студента

Но и:
изменить данные всех студентов,
соответствующих условию

Правило 8. Независимость физических данных

Изменение способа физического хранения данных не должно требовать изменения программ.

Правило 9. Независимость логических данных

Изменения логической структуры должны минимально влиять на приложения.

Правило 10. Независимость ограничений целостности

Правила целостности должны определяться средствами базы данных.

Правило 11. Независимость распределения

Пользователь не должен зависеть от того, где физически находятся данные.

Правило 12. Отсутствие обхода правил

Ограничения реляционной модели не должны обходиться через низкоуровневые механизмы.

Кратко
Правила Кодда задают принципы, которым должна соответствовать полноценная реляционная система.

10. Реляционная алгебра

Реляционная модель описывает структуру данных, а реляционная алгебра описывает операции, которые можно выполнять над отношениями.

Реляционная алгебра
Система операций над отношениями, результатом которых также является отношение.
Таблица → Операция → Новая таблица

Основные операции

  • выборка;
  • проекция;
  • объединение;
  • пересечение;
  • разность;
  • декартово произведение;
  • соединение.

10.1. Выборка (Selection)

σ

Выборка выбирает строки по заданному условию.

ID Фамилия Группа
1 Иванов ИСП-21
2 Петрова ИСП-21
3 Сидоров ИСП-22

Например, можно выбрать только студентов группы ИСП-21.

Запомните
Выборка → строки.

10.2. Проекция (Projection)

π

Проекция выбирает столбцы отношения.

ID Фамилия Имя Группа
1 Иванов Иван ИСП-21
2 Петрова Анна ИСП-21
3 Сидоров Максим ИСП-22

Например, можно получить только фамилии и группы.

Самая важная разница
Выборка → строки.
Проекция → столбцы.

10.3. Объединение

∪

Объединяет элементы двух совместимых отношений. 

Студенты группы ИСП-21
           +
Студенты группы ИСП-22
           ↓
      Все студенты

10.4. Пересечение

∩

Возвращает элементы, которые одновременно принадлежат двум отношениям.

10.5. Разность

−

Возвращает элементы первого отношения, которых нет во втором.

10.6. Декартово произведение

Создаёт все возможные комбинации элементов двух отношений.

Студент Предмет
Иванов Базы данных
Иванов Математика
Петрова Базы данных
Петрова Математика

10.7. Соединение JOIN

Соединение позволяет объединить информацию из нескольких связанных таблиц. 

СТУДЕНТЫ
     │
     │ ID_группы
     ▼
   JOIN
     ▲
     │ ID_группы
     │
   ГРУППЫ
📌 Связь с SQL
SQL — практический язык работы с базами данных, а реляционная алгебра помогает понять теоретическую основу многих операций над данными.

Итоги лекции

Реляционная модель представляет данные в виде взаимосвязанных таблиц. Таблицы состоят из атрибутов и кортежей, записи идентифицируются ключами, а связи между таблицами поддерживаются внешними ключами.

Целостность защищает базу от некорректных ссылок и недопустимых значений, индексы помогают ускорять поиск, а реляционная алгебра описывает операции над отношениями.

🎓 Главное
Умейте связать между собой понятия таблица → ключ → связь → целостность → запрос.

Словарь терминов

Реляционная модель Модель представления данных в виде взаимосвязанных таблиц.
Отношение Таблица в реляционной модели.
Атрибут Столбец отношения.
Кортеж Строка отношения.
Домен Множество допустимых значений атрибута.
Первичный ключ (PK) Уникальный идентификатор записи.
Внешний ключ (FK) Поле, ссылающееся на ключ другой таблицы.
Ссылочная целостность Правило, требующее корректных ссылок между связанными таблицами.
Ограничение целостности Правило, контролирующее корректность данных.
Индекс Структура данных для ускорения поиска.
Правила Кодда Принципы, описывающие свойства реляционной системы.
Реляционная алгебра Система операций над отношениями.

Самопроверка

Сначала попробуйте ответить самостоятельно, затем откройте ответ.

1. Что является основным способом представления данных в реляционной модели?
Таблицы, или отношения.
2. Как называется столбец таблицы?
Атрибут.
3. Как называется строка таблицы?
Кортеж или запись.
4. Для чего нужен первичный ключ?
Для однозначной идентификации каждой записи таблицы.
5. Для чего нужен внешний ключ?
Для связи одной таблицы с другой.
6. Какой тип связи существует между группой и студентами?
Один ко многим — 1:M.
7. Как реализуется связь многие ко многим?
Через промежуточную таблицу.
8. Что такое ссылочная целостность?
Правило, согласно которому внешний ключ должен ссылаться только на существующую запись.
9. Для чего нужен индекс?
Для ускорения поиска и обработки данных.
10. Чем выборка отличается от проекции?
Выборка выбирает строки, а проекция — столбцы.
11. Для чего используется JOIN?
Для объединения информации из нескольких связанных таблиц.
12. Что такое реляционная алгебра?
Система операций над отношениями, результатом которых также является отношение.

Что нужно уметь после лекции

После изучения материала попробуйте без подсказок:

  • определить таблицы и поля для простой предметной области;
  • найти первичный и внешний ключи;
  • определить тип связи между таблицами;
  • объяснить нарушение ссылочной целостности;
  • назвать основные ограничения целостности;
  • объяснить назначение индекса;
  • различать выборку и проекцию;
  • объяснить назначение JOIN.
🎓 Перед следующей темой
Уверенно различайте: отношение → атрибут → кортеж → домен, затем PK → FK → связь → целостность и, наконец, выборка → проекция → JOIN.
