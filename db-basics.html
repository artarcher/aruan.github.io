1. Зачем нужна база данных

Пока данных немного и с ними работает один человек, их можно хранить в обычном файле — например, в таблице Excel. Но при увеличении объёма данных и количества людей, работающих с ними одновременно, возникают проблемы:

  • Дублирование — одна и та же информация хранится в нескольких местах и со временем перестаёт совпадать (например, фамилия студента записана по-разному в разных файлах).
  • Противоречивость — в разных источниках оказываются разные, взаимоисключающие данные об одном и том же объекте.
  • Сложности совместной работы — при одновременном редактировании одного файла несколькими людьми часть изменений может теряться.
  • Медленный и ненадёжный поиск — при большом объёме данных вручную найти нужную информацию по сложному критерию практически невозможно.
  • Отсутствие защиты от ошибок — обычный файл не может автоматически проверить корректность вводимых данных.
База данных (БД)

Организованная совокупность взаимосвязанных данных, хранимая с минимальной избыточностью и предназначенная для многоцелевого использования.

Работой с базой данных управляет специальная программа — система управления базами данных (СУБД). Важно не путать эти два понятия:

База данных СУБД
Сами данные, организованные определённым образом Программное обеспечение, которое создаёт, хранит и обрабатывает базы данных
Пример: база данных «Колледж» Пример: MS Access, MySQL

2. Предметная область

Предметная область

Часть реального мира (объекты, процессы и взаимосвязи между ними), информация о которой подлежит сбору, хранению и обработке в информационной системе.

Предметная область определяет границы: какая информация войдёт в базу данных, а какая — нет, в зависимости от задач, которые база данных должна решать.

Пример

Предметная область базы данных колледжа — учебный процесс: студенты, группы, преподаватели, дисциплины, оценки, расписание. Информация, не связанная с учебным процессом (например, марка оборудования в столовой), в эту предметную область не входит.

3. Объекты (сущности), атрибуты и ключи

3.1. Сущность

Сущность

Отражение в информационной системе объекта или события реального мира, о котором собирается и хранится информация.

Важно различать сущность и её экземпляр:

  • Сущность — это тип, категория (например, «Студент» как понятие).
  • Экземпляр сущности — конкретный представитель этой сущности (например, «Иванов Пётр Сергеевич, № зачётки 20345»).

Примеры сущностей базы данных колледжа: Студент, Группа, Преподаватель, Дисциплина, Оценка, Занятие (расписание).

3.2. Атрибут

Атрибут

Свойство сущности, характеризующее её с определённой стороны и принимающее конкретное значение для каждого экземпляра сущности.

Пример

Атрибуты сущности «Студент»: фамилия, имя, отчество, дата рождения, номер зачётной книжки, номер группы.

Не любая реальная характеристика объекта становится атрибутом в базе данных — только та, которая необходима для решения конкретных задач информационной системы.

3.3. Ключ

Ключ

Атрибут или минимальный набор атрибутов, значение которого однозначно (уникально) идентифицирует каждый экземпляр сущности.

Разновидности ключа, которые нужно различать:

  • Потенциальный ключ — любой атрибут (или набор атрибутов), который в принципе мог бы однозначно идентифицировать экземпляр сущности (например, у студента это может быть и номер зачётки, и номер паспорта).
  • Первичный ключ — тот потенциальный ключ, который выбран для фактического использования в таблице.
  • Составной ключ — ключ, состоящий из нескольких атрибутов одновременно, если ни один из них по отдельности не обеспечивает уникальности.
Пример

Ключом сущности «Студент» является номер зачётной книжки — он не повторяется ни у одного студента, даже если у двух студентов совпадают фамилия, имя и отчество.

Студент
№ зачётки (ключ) Фамилия Имя Группа

4. Модели данных

Модель данных

Способ логической организации данных, определяющий, как данные структурированы и как связаны между собой.

4.1. Иерархическая модель

Данные организованы в виде дерева: каждый элемент (кроме корневого) имеет ровно одного «родителя» и может иметь несколько «потомков».

Пример. Колледж → Факультет → Группа → Студент.

Ограничение. Элемент не может иметь двух «родителей» одновременно. Это неудобно, если, например, один преподаватель ведёт занятия сразу в нескольких группах.

Область применения сегодня. Файловые системы, структура XML-документов.

4.2. Сетевая модель

Развитие иерархической модели: элемент данных может иметь произвольное количество связей с другими элементами, то есть несколько «родителей» одновременно.

Пример. Преподаватель может одновременно относиться сразу к нескольким группам.

Ограничение. Структура значительно сложнее для проектирования и обработки, чем дерево.

4.3. Реляционная модель

Данные представлены в виде набора двумерных таблиц (отношений), а связи между таблицами устанавливаются через совпадающие значения соответствующих атрибутов.

Термин «реляционная» происходит от английского relation — «отношение». В строгом математическом смысле отношение — это множество кортежей (строк с определённым набором атрибутов), а таблица — прикладное представление отношения. В учебных целях таблицу и отношение можно считать синонимами.

Почему реляционная модель стала основной. Она проще для проектирования, чем сетевая, гибче для запросов, чем иерархическая (позволяет легко искать данные по любому критерию), и имеет строгое математическое обоснование (реляционная алгебра, правила Кодда — изучаются на следующих занятиях).

4.4. Развитие способов организации данных

  • Постреляционные модели — допускают хранение в одной ячейке таблицы более сложных, «вложенных» значений (например, список телефонов), в отличие от классической реляционной модели, где ячейка хранит только одно значение.
  • Многомерные модели — организуют данные не в виде плоской таблицы, а в виде многомерного «куба» (например, измерения «студент — дисциплина — семестр»). Используются в системах аналитики (OLAP) и хранилищах данных.
  • Объектно-ориентированные модели — хранят данные как объекты, объединяющие атрибуты и связанное с ними поведение, по аналогии с объектно-ориентированным программированием.

В большинстве практических задач, включая практические работы этого курса, используется реляционная модель данных.

7. Вопросы для самопроверки перед защитой

  1. Почему хранение данных в обычном файле (например, Excel) перестаёт быть эффективным при увеличении объёма данных и числа пользователей?
  2. В чём разница между базой данных и СУБД? Приведите пример каждого понятия.
  3. Что такое предметная область? На примере базы данных колледжа укажите, что входит в предметную область, а что — нет.
  4. Дайте определение сущности. Приведите пример сущности и одного из её экземпляров.
  5. Чем атрибут отличается от сущности?
  6. Что такое ключ? Почему ключ не может повторяться у разных экземпляров сущности?
  7. В чём разница между потенциальным и первичным ключом?
  8. Опишите иерархическую модель данных. Какое у неё ограничение?
  9. Чем сетевая модель отличается от иерархической?
  10. Дайте определение реляционной модели данных. Как устанавливаются связи между таблицами?
  11. Почему реляционная модель данных стала наиболее распространённой?
  12. Назовите модели данных, появившиеся после реляционной, и кратко опишите каждую.

Краткое резюме темы

  • База данных решает проблему надёжного, организованного и совместного хранения больших объёмов данных.
  • Предметная область определяет границы того, какая информация войдёт в базу данных.
  • Сущность, атрибут и ключ — три базовых понятия, описывающих структуру данных: что мы храним, какие у него свойства и как отличить один экземпляр от другого.
  • Существует несколько моделей организации данных: иерархическая (дерево), сетевая (граф связей), реляционная (таблицы со связями через совпадающие значения) — последняя является основной в современных базах данных.
