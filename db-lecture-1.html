1. Почему появились базы данных?

Представим, что в колледже все сведения об обучении студентов хранятся в одной большой таблице.

Фамилия Группа Куратор Предмет Оценка Дата
Иванов ИС-11 Смирнова А.П. Базы данных 5 12.09.2026
Иванов ИС11 Смирнова Базы данных 4 12/09/26
Петров ИС-12 Смирнова А.П. Математика 3 13.09.2026
Иванов ИС-11 Смирнов А.П. Математика 5 13.09.2026

Уже на нескольких строках возникают проблемы. Представьте, что в реальной системе таких записей миллионы.

Основные проблемы хранения данных в одной таблице

Избыточность данных
Одни и те же сведения повторяются много раз. Например, название группы и имя куратора повторяются в каждой записи студента.
Противоречивость данных
Одни и те же факты записываются по-разному. Например: ИС-11, ИС11, ис 11.
Аномалия обновления
Чтобы изменить один факт, необходимо изменить множество записей.
Аномалия вставки
Невозможно добавить информацию об одном объекте, пока отсутствует информация о другом.
Аномалия удаления
При удалении одной записи можно случайно потерять сведения о совершенно другом объекте.

Пример: аномалия обновления

Предположим, куратор группы ИС-11 сменился. Если сведения о кураторе повторяются в каждой строке, необходимо изменить сотни записей.

Проблема
Если хотя бы одну запись забыть изменить, база данных будет содержать противоречивую информацию.

Пример: аномалия вставки

Открылась новая группа, но студенты ещё не зачислены. В большой общей таблице может просто не оказаться места, куда записать сведения о новой группе.

Пример: аномалия удаления

Если удалить единственного студента группы, можно одновременно потерять сведения о самой группе и её кураторе.

Избыточность → Противоречивость → Потеря данных
Решение
Необходимо разделить информацию на отдельные связанные структуры и поручить управление ими специализированной программе — системе управления базами данных.

2. Данные, информация, БД, СУБД и ИС

Данные и информация

Посмотрите на следующий набор символов:

24-101    5    12.09

Без контекста сложно понять, что означают эти значения. Но если добавить описание:

  • 24-101 — номер зачётной книжки;
  • 5 — оценка;
  • 12.09 — дата.

Теперь данные приобретают смысл.

Информация = Данные + Контекст
Данные
Зарегистрированные факты, представленные в формализованном виде и пригодные для хранения, передачи и обработки.
Информация
Данные, помещённые в контекст и осмысленные для решения конкретной задачи.
Дополнительно
Часто используют цепочку: данные → информация → знания. Знания возникают, когда на основе информации выявляются закономерности, позволяющие принимать решения.

База данных

База данных (БД)
Именованная совокупность взаимосвязанных данных, организованных по определённым правилам и отражающих состояние объектов некоторой предметной области.

Важно понимать три особенности базы данных:

  • данные взаимосвязаны;
  • данные организованы по определённым правилам;
  • БД отражает определённую предметную область.

Система управления базами данных

СУБД
Система управления базами данных — комплекс программных средств для создания, хранения, изменения и совместного использования базы данных.
⚠️ Главное различие
БД — это данные.
СУБД — это программа, которая управляет данными.

Основные функции СУБД

  • определение структуры данных;
  • создание базы данных;
  • добавление данных;
  • изменение и удаление данных;
  • поиск и выборка информации;
  • контроль целостности;
  • разграничение прав доступа;
  • поддержка многопользовательской работы;
  • управление транзакциями;
  • резервное копирование;
  • восстановление после сбоев.

Примеры СУБД

  • MS Access;
  • MySQL;
  • PostgreSQL;
  • SQLite;
  • Oracle Database;
  • Microsoft SQL Server;
  • MongoDB — нереляционная СУБД.

Информационная система

Информационная система (ИС)
Совокупность базы данных, СУБД, программных приложений, пользователей и организационных правил, предназначенная для решения задач определённой предметной области. 
ПОЛЬЗОВАТЕЛЬ
      ↕
ПРИЛОЖЕНИЕ
(сайт / программа)
      ↕
СУБД
(MySQL / PostgreSQL)
      ↕
БАЗА ДАННЫХ
(таблицы и данные)
Понятие Что это? Пример
БД Совокупность данных Таблицы студентов и оценок
СУБД Программа для управления БД PostgreSQL
ИС Полная система для решения задач Электронный дневник колледжа
Простая аналогия
База данных — это книги.
СУБД — это библиотекарь.
Информационная система — это вся библиотека вместе с читателями, правилами и системой выдачи книг.

3. Предметная область и структура данных

Предметная область

Предметная область (ПрО)
Часть реального мира, сведения о которой необходимо хранить и обрабатывать в информационной системе.

Примеры предметных областей:

  • колледж;
  • библиотека;
  • аптека;
  • автосервис;
  • фитнес-клуб;
  • кинотеатр.
Важный принцип проектирования
В базе данных хранится не всё, что известно, а только то, что необходимо для работы системы.

Например, в базе колледжа может быть необходимо хранить номер телефона студента, но его любимый музыкальный жанр, скорее всего, не имеет отношения к задачам колледжа.

Объект и сущность

Объект
Конкретный элемент реального мира. Например: конкретный студент Иванов или конкретная группа ИС-11.
Сущность
Тип или класс однородных объектов, о которых необходимо хранить информацию.

Например:

  • Студент — сущность;
  • Иванов Пётр Сергеевич — экземпляр сущности.
В реляционной базе данных:
сущность → таблица;
экземпляр сущности → строка таблицы.

Атрибут

Атрибут
Свойство сущности, характеризующее её экземпляры. В таблице атрибут обычно соответствует столбцу.

Например, для сущности «Студент» атрибутами могут быть:

  • номер зачётной книжки;
  • фамилия;
  • имя;
  • дата рождения;
  • номер группы.

Экземпляр сущности

Экземпляр сущности (запись, кортеж)
Конкретный набор значений атрибутов, описывающий один объект. В таблице соответствует строке.

Домен

Домен
Множество допустимых значений атрибута. Домен включает не только тип данных, но и смысловые ограничения.

Например, атрибут «Оценка»:

  • тип данных — целое число;
  • домен — {2, 3, 4, 5}.

Число 147 является целым числом, поэтому тип данных формально не нарушен. Но значение не принадлежит домену оценки.

Тип данных ≠ домен
Тип отвечает на вопрос: «Какого рода данные?»
Домен отвечает на вопрос: «Какие конкретные значения допустимы?»

Структура сущности «Студенты»

Зачётка Фамилия Дата рождения Код группы
24-101 Иванов 12.05.2008 1
24-102 Петров 03.11.2007 1
  • Таблица — сущность «Студенты»;
  • Столбцы — атрибуты;
  • Строки — экземпляры сущности;
  • Ячейка — значение атрибута.

Виды атрибутов

Тип атрибута Описание Пример
Простой Состоит из одного значения Фамилия
Составной Состоит из нескольких частей ФИО, адрес
Однозначный Для объекта одно значение Дата рождения
Многозначный Может иметь несколько значений Несколько телефонов
Хранимый Значение хранится непосредственно Дата рождения
Вычисляемый Получается на основе других данных Возраст

Основные типы данных

  • INTEGER — целые числа;
  • FLOAT, DECIMAL — вещественные числа;
  • CHAR, VARCHAR — строки;
  • DATE — дата;
  • TIME — время;
  • DATETIME — дата и время;
  • BOOLEAN — логическое значение.

Что такое NULL?

NULL
Специальное значение, означающее, что значение отсутствует или неизвестно.
NULL — это не:
  • не число 0;
  • не пустая строка;
  • не слово «нет».

Например, у обучающегося студента может отсутствовать дата отчисления. В этом случае значение атрибута может быть NULL.

4. Ключи и связи между таблицами

Что такое ключ?

Ключ
Атрибут или набор атрибутов, однозначно идентифицирующий экземпляр сущности.

Например, фамилия не является хорошим идентификатором, потому что могут существовать однофамильцы.

Для студента более подходящим идентификатором может быть номер зачётной книжки или внутренний идентификатор ID.

Первичный ключ — Primary Key (PK)

Первичный ключ (PK)
Атрибут или набор атрибутов, однозначно определяющий каждую строку таблицы.

Требования к первичному ключу

  • Уникальность — значение не повторяется;
  • NOT NULL — значение обязательно должно существовать;
  • Минимальность — ключ не содержит лишних атрибутов;
  • Неизменность — желательно, чтобы значение не менялось со временем.
PK = Уникален · Не NULL · Минимален · Неизменен

Виды ключей

Тип ключа Описание Пример
Простой Состоит из одного атрибута ID студента
Составной Состоит из нескольких атрибутов Студент + Предмет + Дата
Потенциальный Может использоваться как уникальный идентификатор Номер зачётки, паспорт
Первичный Главный выбранный ключ таблицы ID
Альтернативный Потенциальный ключ, не выбранный первичным Уникальный номер документа
Естественный Существует в реальном мире ИНН
Суррогатный Создан специально для БД ID = 1, 2, 3...
Внешний Ссылается на ключ другой таблицы Код группы

Суррогатный ключ

Суррогатный ключ
Искусственный идентификатор, созданный специально для базы данных и не имеющий самостоятельного смысла в предметной области.

Обычно суррогатный ключ представляет собой автоматически увеличивающийся идентификатор: 

ID
1
2
3
4
5

Такой подход удобен, потому что внутренний идентификатор не зависит от изменения фамилии, паспорта или других данных человека.

Внешний ключ — Foreign Key (FK)

Внешний ключ (FK)
Атрибут таблицы, значения которого ссылаются на первичный ключ другой таблицы. 
ГРУППЫ                         СТУДЕНТЫ

Код_гр PK                     Зачётка PK
Название                      Фамилия
                              Код_гр FK
    1  ИС-11        ◄────────      1
    2  ИС-12        ◄────────      1
                              ───── 2

Вместо хранения названия группы в каждой строке студентов хранится только ссылка на соответствующую группу.

Преимущество
Если название группы изменится, его нужно изменить только в одном месте.
Первичный ключ: не повторяется.
Внешний ключ: может повторяться.

Ссылочная целостность

Ссылочная целостность
Правило, согласно которому значение внешнего ключа должно соответствовать существующему значению первичного ключа связанной таблицы либо быть NULL, если это разрешено.

Например, нельзя назначить студенту Код_гр = 99, если группы с таким кодом не существует.

5. Классические модели данных

Модель данных
Совокупность правил, определяющих структуру данных, допустимые операции над ними и ограничения целостности.
1960-е — Иерархическая модель
Данные организованы в виде дерева.
Конец 1960-х — Сетевая модель
Данные представлены в виде графа.
1970 — Реляционная модель
Данные представлены в виде отношений (таблиц).

Иерархическая модель

В иерархической модели данные организованы в виде дерева. У каждого потомка может быть только один непосредственный предок. 

          КОЛЛЕДЖ
         /        \
      ИС-11       ИС-12
      /   \          |
  Иванов  Петров   Сидоров

Преимущества

  • простая структура;
  • высокая скорость доступа по известному пути;
  • экономия памяти.

Недостатки

  • сложно представить связь «многие ко многим»;
  • доступ обычно начинается от корня;
  • структура жёстко связана с путями доступа;
  • удаление родителя может привести к удалению потомков.

Примеры: файловые системы, XML, организационные структуры.

Сетевая модель

Сетевая модель является развитием иерархической. Один объект может быть связан с несколькими другими объектами. Структура напоминает граф. 

ИС-11        ИС-12
  │  \      /   │
  │   \    /    │
Иванов  Петров  Сидоров
    \     |     /
     Базы данных

Преимущества

  • поддерживает сложные связи;
  • может представлять связь «многие ко многим»;
  • эффективна при навигационном доступе.

Недостатки

  • сложная структура;
  • программист должен знать маршруты доступа;
  • изменение структуры может потребовать изменения программ.

Реляционная модель

Реляционная модель была предложена Эдгаром Коддом в 1970 году. Она основана на математическом понятии отношения.

⚠️ Частая ошибка
Слово «реляционная» происходит от английского relation — отношение, а не от слова «связь».

В реляционной модели данные представлены в виде таблиц, а связи между ними устанавливаются через значения ключей.

Преимущества

  • простота и наглядность;
  • строгая математическая основа;
  • независимость данных от программ;
  • использование декларативного языка SQL;
  • широкая распространённость.

Недостатки

  • сложные объекты приходится разбивать на несколько таблиц;
  • для сложных запросов необходимо соединение таблиц;
  • не всегда оптимальна для аналитики огромных объёмов данных.

Примеры реляционных СУБД: PostgreSQL, MySQL, SQLite, Oracle, MS SQL Server, MS Access.

Сравнение классических моделей

Признак Иерархическая Сетевая Реляционная
Структура Дерево Граф Таблицы
Период появления 1960-е Конец 1960-х С 1970 года

6. Развитие моделей данных

Реляционная модель является основной для большинства корпоративных и учебных систем, однако существуют задачи, для которых другие способы хранения данных оказываются удобнее.

Постреляционная модель

Постреляционные модели расширяют традиционный подход и допускают хранение более сложных структур внутри одной записи.

Особенность
В одном поле могут храниться массивы или вложенные структуры.

Например, вместо отдельной таблицы можно представить список книг читателя в виде массива внутри одного поля.

Плюсы

  • связанные данные могут храниться вместе;
  • меньше операций соединения таблиц;
  • удобно работать со сложными структурами.

Минусы

  • сложнее контролировать целостность;
  • часть контроля может переходить к приложению.

Многомерная модель

Многомерные базы данных используются прежде всего для аналитической обработки больших объёмов информации.

  • Срез — фиксируется одно измерение;
  • Вращение — меняются оси анализа;
  • Детализация — переход к более подробным данным;
  • Свёртка — переход к обобщённым данным.

Объектно-ориентированные базы данных

В объектно-ориентированной модели данные хранятся в виде объектов со свойствами и методами.

Поддерживаются принципы ООП:

  • инкапсуляция;
  • наследование;
  • полиморфизм.

Преимущество

Удобное хранение сложных объектов: мультимедиа, чертежей, географических данных, инженерных моделей.

Недостаток

Отсутствует единый универсальный стандарт, сопоставимый по распространённости с SQL.

📌 Итоги лекции

После первой лекции необходимо уверенно понимать следующие идеи.

  1. Базы данных появились как решение проблемы избыточности и противоречивости информации.
  2. БД — это данные, СУБД — программа для управления данными, ИС — более широкая система.
  3. Предметная область определяет, какие данные необходимо хранить.
  4. Сущность соответствует типу объектов, экземпляр — конкретному объекту.
  5. Атрибут описывает свойства сущности.
  6. Домен определяет допустимые значения атрибута.
  7. Первичный ключ уникально идентифицирует запись.
  8. Внешний ключ связывает таблицы.
  9. Наиболее распространённая модель сегодня — реляционная.
  10. Реляционная модель получила название от relation — «отношение», а не от слова «связь».

🧠 Самопроверка

Попробуйте сначала ответить самостоятельно, а затем откройте правильный ответ.

1. Почему хранение всех данных в одной большой таблице опасно?
Возникают избыточность, противоречивость, аномалии обновления, вставки и удаления.
2. Чем данные отличаются от информации?
Данные являются зарегистрированными фактами. Информация — это данные, осмысленные в определённом контексте.
3. Чем БД отличается от СУБД?
БД — это сами данные. СУБД — программная система для управления этими данными.
4. Что является сущностью, а что экземпляром?
«Студент» — сущность. «Иванов Пётр» — экземпляр сущности.
5. Чем тип данных отличается от домена?
Тип определяет вид данных, например «целое число». Домен дополнительно ограничивает допустимые значения, например оценка может принимать только 2, 3, 4 или 5.
6. Может ли первичный ключ повторяться?
Нет. Значение первичного ключа должно быть уникальным.
7. Может ли внешний ключ повторяться?
Да. Например, у многих студентов может быть один и тот же код группы.
8. Почему связь «многие ко многим» требует промежуточную таблицу?
Потому что одна таблица не может напрямую хранить множество повторяющихся связей без нарушения нормальной структуры данных. Промежуточная таблица содержит ссылки на обе связанные сущности.
9. Почему модель называется реляционной?
От английского слова relation — «отношение». В математическом смысле отношение соответствует таблице.
10. Что означает NoSQL?
Not Only SQL — «не только SQL». Это семейство различных нереляционных моделей данных.
